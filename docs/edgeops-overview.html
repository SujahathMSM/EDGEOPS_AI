EDGEOPS AI

Evidence-backed operations through typed, capability-limited tools

An AI-assisted operations platform: instead of giving an AI agent free shell access, it investigates incidents through strictly typed tools, works only from collected evidence, proposes fixes that humans approve, and verifies the result. Deterministic tools collect facts · local models compress facts · stronger models reason only on escalation · humans approve changes.

Target: SRE / DevOps engineers, Dockerized services, industrial systems (Modbus, BMS)
Stack: Python 3.11+ · Pydantic 2 · future FastAPI + PostgreSQL/pgvector + local Ollama
Status: Stage 1 complete — typed tool foundation

Every tool execution follows the same pipeline

1
Request
Trusted caller supplies Actor + ToolRequest
2
Validate
Strict Pydantic, no unknown fields, no coercion
3
Resolve
Registry lookup — unknown tool → error
4
Arguments
Tool's input schema validates arguments
5
Policy
Permission + exact target scope + risk level
6
Target check
Tool-specific validator must return True
7
Execute
Async adapter under cooperative timeout
8
Normalize
Output revalidated, secrets recursively redacted
9
Audit
Event on every path — success, failure, denial, cancel
10
Result
Envelope with UTC time, duration, evidence + correlation IDs

Policy decision — the heart of the safety design

Allow automatically
READ_ONLY tools with the right permission and in-scope target (host, resource, environment)
Require approval
LOW / MEDIUM / HIGH risk actions → APPROVAL_REQUIRED. Nothing mutates anything in Stage 1
Deny
FORBIDDEN tools, missing permission, or out-of-scope target → POLICY_DENIED

Deliberately NOT in this project (the "prevent the chatbot" rules)

No arbitrary shell
The design guards against this becoming an un-auditable AI shell runner
No autonomous actions
Models may propose actions but can never bypass policy or approval
No undocumented causality
Hypotheses must link evidence IDs; "root cause" requires verified recovery
No premature scaling
No Kubernetes, microservices, or message buses until real workload needs them
